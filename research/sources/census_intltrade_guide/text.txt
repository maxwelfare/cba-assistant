This user guide explains how to access the Monthly International Trade Datasets and their
associated meta-data as published in the Census API. It also serves as an informational resource
about the datasets. This guide assumes that you already have some familiarity with the
concepts and techniques of retrieving data from web services. See the International Trade
Developers Page for more information.

The International Trade Query Builder Tool is a live-connection graphical user interface to the
Monthly International Trade Datasets. For new users of the API this tool is an easy method of
constructing a properly formatted API call. For more experienced users this tool is an effective
shortcut to building complex API calls.

An API Key is needed to access the Census API. A Key is a 40-character string that you append to
the end of your API calls in the following format: &key=<your 40 character key>.
To request a Key register at https://api.census.gov/data/key_signup.html. To register, you must
provide your name (or organization name), a valid email address, and agree to the published
terms of service.
After completing the registration form, you will receive an email containing your assigned API
Key and an activation link. You must click on the link to activate your Key.

aggregated by NAICS codes then choose the Export NAICS endpoint. HS, NAICS, EndUse, SITC, USDA, and Advanced Technology endpoints all have district and country level
detail and totals.

Use the URIs above to access the Monthly Trade Datasets in the Census API. You can
retrieve data by sending an HTTPS GET to the URI with the appropriate (querystring)
parameters. A comprehensive list of available export and import parameters is found in
appendices A and B.

For reasons of space and clarity, the following API call examples will not include an
API Key. API calls without an API Key will fail.

When unspecified, the default API data format is the Javascript Object Notation (JSON) format. There is
also an option to obtain a comma-delimited file by specifying &outputFormat=csv.

There are currently 56 export parameters (appendix A) and 85 import parameters (appendix B) in the
Monthly International Trade Datasets. Note that not all variables are available in each endpoint. The
following section gives guidance on how to use these parameters correctly.
Time Parameters
Calls must include either the time or YEAR/MONTH parameters. The following API call will result in the
following message: “error: missing required variable/predicate: time”.
https://api.census.gov/data/timeseries/intltrade/imports/hs?get=DISTRICT,DIST_NA
ME,GEN_VAL_YR
Adding a specified time parameter or YEAR/MONTH to the API call resolves the error.
https://api.census.gov/data/timeseries/intltrade/imports/hs?get=DISTRICT,GEN_VA
L_YR&time=2013-03

There are two methods of requesting a custom time range. The time parameter has a native syntax for
date ranges where adding “&time=from+2022-03+to+2022-07” will return data from March – July 2022.
6

That same date range requested using the YEAR/MONTH combination is done as follows:
“&YEAR=2022&MONTH=03&MONTH=04&MONTH=05&MONTH=06&MONTH=07”.
Because ‘time’ is an API defined parameter, and not a variable defined in the dataset, it uses
more processing resources, leading to more frequent API timeout errors. For larger requests we
recommend using YEAR/MONTH.

Default Values for Parameters
The default value for all string type parameters is a dash (-). This means that calls that do not apply
filtering parameters will return the total value for the specified string parameter. For example, the
following call has no defined parameters other than ALL_VAL_MO, meaning the result will return a total
value for that variable in that endpoint and time.
https://api.census.gov/data/timeseries/intltrade/exports/hs?get=ALL_VAL_MO&time=2013-01
[["ALL_VAL_MO","time"],
["123031879061","2013-01"]]

Adding the parameters for country (CTY_CODE or CTY_NAME), HS (E_COMMODITY), district (DISTRICT),
and/or domestic/foreign (DF) will return the total value of all countries, HS codes, districts, and/or DF
values in January 2013. If you add the country code parameters (CTY_CODE,CTY_NAME) to your call,
then your call will return the total export value for January 2013 broken down by country.
https://api.census.gov/data/timeseries/intltrade/exports/hs?get=CTY_CODE,CTY_NAME,ALL_VAL_M
O&time=2013-01
[["CTY_CODE","CTY_NAME","ALL_VAL_MO","time"],
["-","TOTAL FOR ALL COUNTRIES","123031879061","2013-01"],
["1010","GREENLAND","233446","2013-01"],
["1220","CANADA","23170845914","2013-01"],

meaning “TOTAL FOR ALL COUNTRIES” may not always appear as the first record.
Changing the sort order must be done outside of the API.

Invalid Combination of Parameters
There are six different commodity classification systems available in the API for exports and imports.
Two of these systems, the Harmonized System (HS) and End-Use, have different codes for exports and
imports, while the rest of the codes are the same for exports and imports. End-Use, NAICS, SITC, USDA,
and HITECH classification codes are derived from the collection of Harmonized System codes
(E_COMMODITY for exports and I_COMMODITY for imports). You can map which HS codes are included
in End-Use, NAICS, SITC, USDA, and HITECH codes using the year vintage concordance as a guide.
A successful API call references only one endpoint and its associated parameters, do not attempt to
combine more than one classification system endpoint of parameters into an API call or you will get an
error.

Valid Request with No Results
If an API call returns no results that does not necessarily mean there is an error. It may mean that there
is no data for that combination of parameters. As mentioned above, a successful request with no results
returns HTTP status code 204. As an example, the API call below returns an HTTP status code of 204
meaning it is a valid request, but the U.S. did not export any soybeans to the Dominican Republic in
January of 2013.
https://api.census.gov/data/timeseries/intltrade/exports/enduse?get=E_ENDUSE
,E_ENDUSE_LDESC,CTY_CODE,ALL_VAL_MO,ALL_VAL_YR&YEAR=2013&MONTH=
01&CTY_CODE=2470&E_ENDUSE=00100
Units of Quantity
Units of Quantity are only available in the Harmonized System (HS) endpoints and only for the most
detailed, 10-digit HS code level. These two quantity parameters (UNIT_QY1 and UNIT_QY2) return the
unit of measurement for the corresponding QTY_1 and QTY_2 variables.
https://api.census.gov/data/timeseries/intltrade/exports/hs?get=E_COMMODIT
Y,E_COMMODITY_LDESC,UNIT_QY1,UNIT_QY2,ALL_VAL_MO,QTY_1_MO,QTY_1_
MO_FLAG,QTY_2_MO,QTY_2_MO_FLAG&time=2016-05
https://api.census.gov/data/timeseries/intltrade/imports/hs?get=I_COMMODIT
Y,I_COMMODITY_LDESC,UNIT_QY1,UNIT_QY2,GEN_VAL_MO,GEN_QY1_MO,GE
N_QY1_MO_FLAG,GEN_QY2_MO,GEN_QY2_MO_FLAG&time=2016-05

Notice the the QTY_1_MO_FLAG and QTY_2_MO_FLAG parameters in the calls? See the
next section for why those are strongly recommended when using UNIT_QY1 and
UNIT_QY2.

Missing Value Flags
Occasionally the QTY_1 and QTY_2 variables have missing values. Because this means that some zero quantity
values returned by the API are not true zeros, but are instead missing values, there are variables to alert you that
the data is not a true zero. Both QTY variables have a Missing Value Flag parameter (QTY_1_MO has a
QTY_1_MO_FLAG) that should always be paired in an API call. The FLAG parameter will be equal to “M” when a
value is missing, otherwise it will be blank field denoting a true zero.

https://api.census.gov/data/timeseries/intltrade/exports/hs?get=E_COMMODITY,ALL_VAL_
YR,QTY_1_MO,QTY_1_MO_FLAG&time=2013-01&COMM_LVL=HS2

Hexadecimal Equivalents
Certain special characters needed for a filering variable (e.g. Country Subcode J+ or A*) are shared with
functions in API calls, so including them may return unexpected results. To avoid this use the
hexadecimal equivalents of those characters:
https://api.census.gov/data/timeseries/intltrade/imports/hs?get=CTY_SUBCO
DE,GEN_VAL_MO&time=2013-01&CTY_SUBCODE=P%2B
https://api.census.gov/data/timeseries/intltrade/imports/hs?get=CTY_SUBCO
DE,GEN_VAL_MO&time=2013-01&CTY_SUBCODE=P+

Because the amount of data available in the Monthly International Trade Datasets it can be very easy for
users to overwhelm the API’s ability to respond. When this happens users will experience slow
performance or system timeouts. As an example, a single query pulling data for all countries and all HS
commodities will almost always result in a time out error. Even with other classification systems or a
more limited selection of variables these timeouts are possible. The occurrence of these events is
unpredictable because the cardinality of the data returned by a request will vary by month, year,
commodity, and geography. It can happen that a data call that functioned perfectly when requesting
April data will time out when requesting that same report for November because that month had more
trade partners or other data points that rapidly multiply the number of unique items in the response.
For this reason our recommended best practice is to query the API with many smaller data calls that
always return results rather than larger data calls that will potentially fail. This is particularly critical for
an automated data retrieval process. Users have regularly succeeded in retrieving the complete Monthly
International Trade Datasets from the API by limiting the size of their query by breaking up the call and
recombining the results. One useful tool to accomplish this is to generalize your request by using a wild
card “*”.

The two parameters SUMMARY_LVL and SUMMARY_LVL2 in the International Trade Datasets allow you to define
different levels of data summarization.
SUMMARY_LVL
SUMMARY_LVL has only two potential values: CGP and DET. CGP indicates common country groupings including
geographic regions (e.g. Africa), international organizations (e.g. European Union), or free trade agreements (e.g.
USMCA). “DET” indicates individual trading partner data. The SUMMARY_LVL parameter allows you to limit the
returned data to individual trade partners (&SUMMARY_LVL=DET) or to country groupings
(&SUMMARY_LVL=CGP). It also allows you to see sort and group country groupings apart from individual partners.

The second parameter representing different levels of data summarization is SUMMARY_LVL2, which allows you to
request all unique combinations of specified parameters from the API. For example, the SUMMARY_LVL2
parameter can be asked to pull all combinations of NAICS (NA), CTY_CODE (CY), and Domestic/Foreign (DF) by
submitting the following API call:
